Checkbox

Open in Figma ↗

Checkbox on its own, with a label and description, or in a group. Checked, indeterminate, error, read-only, disabled and skeleton; Themed and Inverse.

Usage

<label class="bog-checkbox">
  <input type="checkbox" class="bog-checkbox__input">
  <span class="bog-checkbox__text">
    <span class="bog-checkbox__label">I agree to the <a href="#">terms ↗</a></span>
    <span class="bog-checkbox__desc">Description</span>
  </span>
</label>

<fieldset class="bog-checkbox-group" data-state="error">
  <legend class="bog-checkbox-group__label">Notifications</legend>
  …checkboxes…
</fieldset>

Try it

Tick the options. The box turns orange and the check draws itself along its path while it grows in with a small overshoot; unticking shrinks it away. Tick some but not all and "All notifications" turns indeterminate — its dash grows out from the centre.

Motion

Same speeds as Radio Button. Ticking turns the box orange in 250 ms while the check grows from nothing to full size in 333 ms, overshooting a little before it settles — and its path draws on, short leg then long leg, in 250 ms. Unticking shrinks the check away in 150 ms while the box empties. The indeterminate dash grows out from its centre. BOG UI proposal — there is no Checkbox guide in Component Motion Guidelines yet. Timings and curves are the Radio Button ones; check them with design.

A checkbox view: the box colour and the mark's scale each get their own animation, so each runs with its own curve.

A composable with animate*AsState values for the box colour and the mark scale. ToggleableState.Indeterminate shows the dash.

Checked ↔ unchecked colour and scale are CSS transitions in checkbox.css; the check's path draw and the moves in and out of Indeterminate run in bog-ui.js on every change; if you set .indeterminate in code, call BOG.checkboxSync() afterwards.
